✅ SOLUÇÃO RECOMENDADA:
════════════════════════════════════════════════════════════════════════════════

NÃO precisa enviar CSVs para GitHub!

Por quê? Porque agora você usa Supabase (banco de dados na nuvem)
Os CSVs são temporários → pipeline.py lê e manda para Supabase

Você pode:

OPÇÃO 1: Ignorar CSVs no GitHub (RECOMENDADO)
─────────────────────────────────────────────

1. Arquivos CSV NÃO precisam estar no repositório
2. Coloque localmente em: input/
3. Execute: python pipeline.py
4. Dados vão para Supabase
5. CSVs não precisam ir para GitHub

Vantagens:
  ✅ Repositório fica menor
  ✅ Não polui o Git com dados
  ✅ Dados estão sempre no Supabase


OPÇÃO 2: Ignorar apenas o arquivo grande
─────────────────────────────────────────

1. Abra arquivo: .gitignore
2. Procure a seção # Dados e cache
3. Adicione esta linha:

   input/motorista*.csv

4. Assim esse arquivo não será enviado, mas outros CSVs sim
5. Salve e commita

Vantagens:
  ✅ Outros CSVs continuam versionados
  ✅ Apenas o grande é ignorado


OPÇÃO 3: Dividir arquivo em partes
─────────────────────────────────────

Se REALMENTE precisa versionar o arquivo:

1. Abra arquivo: motorista não identificado 15-02 à 22-02.csv
2. Abra no Excel
3. Divide em 2 arquivos:
   - motorista_parte1.csv (primeiras 50.000 linhas)
   - motorista_parte2.csv (próximas 50.000 linhas)
4. Deleta o original grande
5. Carrega as duas partes

Desvantagem:
  ❌ Mais complicado
  ❌ Precisa juntar depois


OPÇÃO 4: Usar Git LFS (Large File Storage)
──────────────────────────────────────────

Para arquivos muito grandes:

1. Instale Git LFS: https://git-lfs.github.com
2. No PowerShell:
   git lfs install
3. Configure o arquivo:
   git lfs track "*.csv"
4. Commit normalmente

Precisam:
  ❌ Mais setup
  ❌ Requer Git LFS no servidor
